AList File Manager — Privacy Policy

Version 3.66.0 · Last updated: 19 November 2026 · Publisher: Moechz (moechz@163.com)

本文档为中英双语隐私政策：英文版在前，中文版在后，两版内容一致。

1. Overview

AList File Manager is a self-hosted file aggregation program that runs entirely on your own NAS device (TerraMaster TOS 7). The application itself does not collect, transmit or share any personal data with the publisher or any third party. There is no analytics, no telemetry, no tracking, no advertising SDK and no crash reporting. The developer operates no server in this path and cannot see your data.

3. Retention period

  • No automatic expiry. The database, configuration, search index and logs stay in /var/lib/alist until you delete them or uninstall the application.
  • Uninstalling deletes the data. In this version an uninstall (App Center “Uninstall”, dpkg --remove, or apt remove) removes /var/lib/alist completely, because the package specification requires uninstall to leave no residual data. Back up /var/lib/alist before uninstalling if you want to keep your library.
  • Upgrading keeps the data. Installing a newer version only stops and restarts the service; the database is migrated in place and preserved.
  • Initial password file — retained until you delete it or uninstall; it is root-readable only (0600).
  • Logs — the service logs to the system journal (governed by the NAS journal rotation settings, not by this package). The maintenance log /var/log/alist-maint.log records install/uninstall steps and is removed on uninstall.
  • Website (moechz.com) — unrelated to this application; see www.moechz.com/privacy.html.

4. Your rights

  • Access / export — log in to the web UI (all storages, users and settings are visible there), copy /var/lib/alist as the NAS administrator, or use AList's own API/WebDAV export paths.
  • Correction — change settings in the web UI or edit /usr/local/alist/alist.env, then restart the service.
  • Deletion — delete accounts, storages and share links in the web UI; remove everything with an uninstall (see §5) or rm -rf /var/lib/alist.
  • Restriction — per-storage visibility and per-user permissions in the UI; the guest account is disabled by default and the backend listens on loopback only.

5. Deletion channel

  • Self-service (immediate) — App Center “Uninstall” or dpkg --remove alist deletes the database, configuration, password file, logs, service registration and the dedicated user. Removing the folder /var/lib/alist deletes the data without uninstalling.
  • E-mail — moechz@163.com (subject “AList data request”) for questions or requests about the package, the listing or the publishing records; a reply follows within 30 days. The developer holds no copy of your data, so deletion on your NAS is complete by itself.
  • Issues — github.com/Moechz/alist/issues.

6. Security measures

  • The service runs as the dedicated unprivileged system user alist (no shell, no home directory), never as root.
  • systemd sandbox: NoNewPrivileges=true, ProtectSystem=strict, ProtectHome=true, PrivateTmp=true, ProtectKernelTunables/Modules/Logs, ProtectControlGroups, ProtectClock, ProtectHostname, ReadWritePaths=/var/lib/alist, UMask=0027, LimitNOFILE=65536.
  • The backend listens on 127.0.0.1 only (no port is exposed to the LAN); access goes through the TOS web server route /alist/ with the platform's authentication and TLS.
  • Credential files are minimal: config.json 0640, admin_password.txt 0600 root-only; package files are not world-writable.
  • Passwords are stored as hashes; share links use random tokens and can be revoked in the UI.
  • If you enable FTP/SFTP/S3 listeners in alist.env, you are responsible for their credentials, ports and firewall rules.

7. Third-party network access and API disclosure

The application makes network requests only for operations you initiate. Every storage backend sends the credentials you entered and the file operations you perform directly from your NAS to the provider you chose. No data is sent to the publisher; there is no telemetry and no automatic phone-home.

8. Accounts and children

The application has a purely local account system (an administrator plus optional users; the guest account is disabled by default). It is a self-hosted utility, not directed at children and does not knowingly process children's data.

9. Changes and contact

This policy ships inside the application package (/usr/local/alist/privacy-policy.html), is served by the app at /alist/privacy-policy.html, and is also published at github.com/Moechz/alist/PRIVACY.md. Material changes are reflected in the “Last updated” date.

AList File Manager — 隐私政策（中文）

版本 3.66.0 · 最后更新：2026 年 11 月 19 日 · 发布者：Moechz（moechz@163.com）

1. 概述

AList File Manager 是完全运行在您自己的 NAS 设备（TerraMaster TOS 7）上的自托管文件聚合程序。应用本身不向发布者或任何第三方收集、传输、共享任何个人数据：无统计、无遥测、无跟踪、无广告 SDK、无崩溃上报。开发者在整条链路上没有任何服务器，也无法看到您的数据。

2. 处理哪些数据、存在哪里

数据位置用途
用户账号（用户名、口令散列、偏好）/var/lib/alist/data.db本地登录与用户设置
您配置的存储凭据（OAuth/刷新令牌、访问密钥、WebDAV/S3/FTP 口令）/var/lib/alist/data.db连接您自己添加的存储；不会上传给发布者
初始管理员密码/var/lib/alist/admin_password.txt（仅 root，0600）首登一次性凭据；改密后建议删除

以上数据全部留在设备上，应用不会将其上传给发布者或任何中间方。

3. 保留期限

  • 无自动过期。数据库、配置、搜索索引与日志保存在 /var/lib/alist，直到您删除或卸载应用。
  • 卸载会删除数据。本版本中，卸载（应用中心「卸载」、dpkg --remove 或 apt remove）会完整删除 /var/lib/alist——因为包规范要求卸载后不留残余数据。若需保留文件库，请在卸载前备份 /var/lib/alist。
  • 升级会保留数据。安装新版本只停服务并重启，数据库就地迁移并保留。
  • 初始密码文件——保留到您删除或卸载；仅 root 可读（0600）。
  • 日志——服务日志写入系统 journal（由 NAS 的 journal 轮转策略管理）；维护日志 /var/log/alist-maint.log 记录安装/卸载步骤，卸载时一并删除。
  • 网站（moechz.com）——与本应用无关，见 www.moechz.com/privacy.html。

4. 您的权利

  • 访问/导出——登录网页界面（存储、用户、设置均可见）；以 NAS 管理员身份复制 /var/lib/alist；或使用 AList 自带的 API/WebDAV 导出路径。
  • 更正——在网页界面修改设置，或编辑 /usr/local/alist/alist.env 后重启服务。
  • 删除——在网页界面删除账号、存储与分享链接；卸载（见 §5）或 rm -rf /var/lib/alist 可清除全部数据。
  • 限制——界面中按存储设置可见性与用户权限；访客账号默认禁用；后端仅监听回环地址。

5. 删除渠道

  • 自助（立即生效）——应用中心「卸载」或 dpkg --remove alist 会删除数据库、配置、密码文件、日志、服务注册与专用用户；直接删除 /var/lib/alist 目录即可在不卸载的情况下清除数据。
  • 邮件——moechz@163.com（主题「AList data request」）：用于就本包、商店条目或发布记录提问，30 天内答复。开发者不持有您数据的任何副本，因此您 NAS 上的删除即为彻底删除。
  • Issue——github.com/Moechz/alist/issues。

6. 安全措施

  • 服务以专用非特权系统用户 alist 运行（无 shell、无家目录），绝不以 root 运行。
  • systemd 沙箱：NoNewPrivileges=true、ProtectSystem=strict、ProtectHome=true、PrivateTmp=true、内核参数/模块/日志保护、ProtectControlGroups、ProtectClock、ProtectHostname、ReadWritePaths=/var/lib/alist、UMask=0027、LimitNOFILE=65536。
  • 后端仅监听 127.0.0.1（不向局域网另外开放端口），访问经 TOS 网页服务的 /alist/ 路由，沿用平台的身份认证与 TLS。
  • 凭据文件权限最小化：config.json 0640、admin_password.txt 0600（仅 root）；包内文件不可被任意用户写入。
  • 口令以散列形式存储；分享链接使用随机令牌，可随时在界面撤销。
  • 若您在 alist.env 中启用 FTP/SFTP/S3 监听，其凭据、端口与防火墙规则由您负责。

7. 第三方网络访问与 API 披露

应用仅在您主动发起操作时访问网络。每个存储后端都会把您填写的凭据与您执行的文件操作，由您的 NAS 直接发送给您选择的服务商；不会向发布者发送任何数据，也无遥测、无自动回连。

8. 账户与儿童

应用仅具备本地账号体系（管理员 + 可选用户，访客账号默认禁用）。本应用为自托管工具，不面向儿童，也不会在知情情况下处理儿童数据。

9. 变更与联系

本政策随应用包分发（/usr/local/alist/privacy-policy.html），应用内亦经 /alist/privacy-policy.html 提供，并同时发布在 github.com/Moechz/alist/PRIVACY.md。实质性变更会同步更新「最后更新」日期。
